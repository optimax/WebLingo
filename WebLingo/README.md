# WebLingo

WebLingo is a JavaScript-inspired, cross-platform server-side scripting language. This is its M0.6 implementation: a compiler and a register VM for a first subset of the language, not yet a complete one.

The intended project domain is `weblingo.dev`.

## What runs

M0.6 compiles and runs `.wlg` scripts made of `var` and `const` declarations, integer and binary64 literals (`10`, `1.5`, `1e21`, and the keywords `Infinity` and `NaN`), `+ - * /` (where `/` gives a binary64: `10 / 2` is `5.0`), parentheses, assignment, unary `+`, `-` and `!`, `true`, `false` and `null`, the comparisons `== != < <= > >=`, `&&` and `||`, blocks `{ … }`, `if` and `else`, `while`, `for` and `do … while` with `break` and `continue`, string literals (`"a"` or `'a'`, with escapes) and their concatenation with `+`, multi-line raw strings (`"""…"""` or `'''…'''`, their indentation removed), interpolated strings (`$"Hello, {name}!"`, `$$"""{ "n": {{n}} }"""`), with formats and alignments (`$"{price,10:N2}"`), functions (`function f(a) { return a; }`, function expressions, arrow functions (`(a, b) => a + b`, `x => { … }`, `async x => …`), closures, built-ins as values, and default values, `function f(a, b = 1)`), a string's `length` and its characters by index (`s.length`, `s[i]`), arrays (`[1, "a"]`, `a[i]`, `a[i] = v`, `a.length`, `a.push(v)`, `a.pop()`), maps (`{ name: "x", "n": 1 }`, `m[k]`, `m[k] = v`, `m.has(k)`, `m.remove(k)`, `m.length`, and `m?[k]`, which gives `null` for an absent key), classes (`class Point { constructor(x) { this.x = x; } get() { return this.x; } }`, `new Point(1)`, fields, methods, `p?.name`, `class B extends A` with `super(…)` and `super.name(…)`, static members (`static var n = 0;`, `static f() { … }`, `A.f()`, `A.n`), properties (`property area { get { return this.w * this.h; } set(value) { … } }`, with `field`, a property's own field), classes made while the program runs (`var Point = new Class("Point");`, `Point.setMethod("describe", function (this, prefix) { … });`, a function with a receiver, `this`, as its first parameter, `__className`, `__instanceOf` and `__parent`, `setProperty`, `setStaticProperty`, `setConstant` and `static const`, and metaclasses, `class Entity extends Class { … }`, whose instances are classes), every class extending `Object`, whose `equal(other)` and `toString()` a class may override (`write` then writes what `toString()` gives, and `n.toString()` gives any value's text), exceptions (`throw`, `try`, `catch` and `finally`, and `Error`, which a caught runtime error becomes), typed catches (`catch (KeyError e)`, several catches, every runtime error an instance of its kind's class), `x is Point` and every value's class (`5 is Integer`), classes extending `Array`, `Map` and `Set` (`class Stack extends Array { … }`), or `Boolean`, `Integer`, `Number` and `String`, whose instances hold a value (`class Celsius extends Number { … }`, `new Celsius(21.5)`, written `Celsius:21.5`), a string read as a value (`Integer.parse("10")`, `Number.parse("1.5")`, `Boolean.parse("true")`, and `new Integer("10")`), or `Function`, whose instances are functions with methods of their own, operators a class declares (`static operator +(a, b) { … }`), `extend` blocks, which give a class, or a kind of value's, methods and static members (`extend Integer { isPositive() { return this > 0; } }`), static members added by assignment (`Point.origin = …`), and `dispose()` or `destructor()`, run once, a derived class's then its base's, by `x.dispose()` or at the end of `using (var r = new R()) { … }`), sets (`#{1, "a"}`, `s.add(v)`, `s.has(v)`, `s.remove(v)`, `s.length`), `foreach (var x in a)` over an array or a string and `foreach (var (k, v) in m)` over a map, modules (`import db from "lib/db.wlg";`, `import { f } from "util";`, `export` before a declaration, parameters, `param size = 10;`, `import box from "box" { size: 1 };`, and a script's own, given as strings by `weblingo run script.wlg size=10 name=Anna`, and imports while the program runs, `var db = await Module.import("lib/db");`; `samples/Modules`), `async` functions and `await` (`async function f() { … }`, `async` methods and function expressions, `await t` in them and at a script's top level, `x is Task`, `t.forget()`, `Task.all([…])`, `Task.any([…])`, `Task.timeout(t, milliseconds)`, also the exports of the standard module `std:tasks`, and an `async` `dispose()`, which `using` awaits), and the built-ins `write` (the value as text), `writeLn` (the same, then a line break) and `delay(milliseconds)` (a task that completes once that time has passed):

```javascript
import { writeLn } from "std:console";
var a = 10;
var b = 20;
var result = a + b;
writeLn(result);   // 30
```

Every variable is initialized where it is declared, and a name means nothing before its declaration (both are compile-time errors); integer overflow is a runtime error. `samples/HelloWorld`, `samples/Arithmetic` and `samples/Modules` run.

## Pages

WASP pages, Web Application Server Pages, are `.wasp` templates, compiled by the template compiler (`WebLingo.Templates`) into WebLingo, and run by `wasp`, their command line (`src/WebLingo.Wasp.Cli`). A page's text is written as it stands; `<% … %>` holds statements, which may span several blocks, the text between them in their body; `<%= x %>` writes `x`'s text escaped for where it stands in the page's HTML, its text, an attribute, a URL, a script or a style, as Go's `html/template` escapes it, `<%- x %>` as it stands, and either nothing for `null`; and `<%# … %>` is a comment. A line holding only `<% … %>` blocks and spaces writes nothing, not even its line break:

```html
<% param who = "you & me"; %>
<ul>
<% foreach (var i in [1, 2]) { %>
  <li>Item <%= i %> for <%= who %></li>
<% } %>
</ul>
```

writes `<ul>`, then `<li>Item 1 for you &amp; me</li>` and the same for 2, each on a line of its own, then `</ul>`. `<% include "/includes/header.wasp"; %>` reads a template in its place, as if its text stood there: a path starting with `/` is from the application's root, which `wasp run --root site page.wasp` gives (the page's folder when it is left out), any other from the including file's folder. `await renderComponent("/components/card.wasp", { product: p });` renders a component, a page with a scope of its own, found and compiled when it is first rendered, which declares the values it takes as parameters, `<% param product; param size = "small"; %>`. `<% layout "/layouts/main.wasp", { title: "Products" }; %>`, after a page's parameters and imports and before anything else, runs the layout, a template with parameters of its own, which writes the rest of the page where it calls `renderBody()`. `samples/SimpleWebsite` has a layout, an include and a component: `dotnet run --project src/WebLingo.Wasp.Cli -- run samples/SimpleWebsite/index.wasp`.

## Commands

```sh
dotnet restore WebLingo.slnx
dotnet build WebLingo.slnx -c Release
dotnet test WebLingo.slnx -c Release
dotnet run --project src/WebLingo.Cli -- run samples/Arithmetic/arithmetic.wlg
dotnet run --project src/WebLingo.Cli -- check samples/Arithmetic/arithmetic.wlg
dotnet run --project src/WebLingo.Cli -- compile samples/Arithmetic/arithmetic.wlg
dotnet run --project src/WebLingo.Cli -- run samples/Arithmetic/arithmetic.wlb
dotnet run --project src/WebLingo.Cli -- disasm samples/Arithmetic/arithmetic.wlb
dotnet run --project src/WebLingo.Cli -- --version
dotnet run --project src/WebLingo.Wasp.Cli -- run page.wasp
dotnet run --project src/WebLingo.Wasp.Cli -- serve --root ../Examples.wasp/example1
dotnet run --project src/WebLingo.Wasp.Cli -- fastcgi --root ../Examples.wasp/example1 --port 9000
dotnet run --project benchmarks/WebLingo.Benchmarks -c Release
```

The last command times the VM on the benchmark's workloads (`benchmarks/WebLingo.Benchmarks/Workloads`), and writes the results as a table; given `-- --compare`, it times WebLingo against JavaScript, Python and Lua instead, on the programs in `benchmarks/WebLingo.Benchmarks/Comparative`, with the Node.js, Python and Lua it finds on the PATH.

`weblingo run <file>` compiles a script and runs it, as `weblingo <file>` does, the file named first, a `.wlg` or a bytecode file; `weblingo check <file>` compiles it and reports its errors without running it. `weblingo compile <file>` writes its bytecode, a `.wlb` file beside it. `weblingo run <bytecode-file>` runs verified bytecode, and `weblingo disasm <bytecode-file>` shows the instructions. Earlier builds' `.wlbr` and `.wlbc` files are still accepted, and the stack VM's `.wlbs` refused. `weblingo run` of a `.wlg` compiles it in memory and writes no bytecode file, and `wasp` never writes one. A script imports a native module, an assembly in a folder its host is configured with, by a scheme, `import db from "native:sqlite";`, or by the assembly's path within such a folder: `weblingo run --scheme native=C:/WebLingo/native script.wlg`, or a `weblingo.config` in the script's folder, `{ "schemes": { "native": "C:/WebLingo/native" } }`, names the folders. A native module's exports are functions and classes, whose instances may hold .NET objects of their own. `std:fs` reads and writes files: `import fs from "std:fs";`, then `await fs.readText(path)`, or `fs.readTextSync(path)`, and `fs.writeText`, `appendText`, `exists`, `remove`, `list`, `makeFolder`, `removeFolder` and `File.open(path, mode)`, a failure an `IOError`. `std:http` and `std:net` reach other servers, `await http.get(url)`, `http.post(url, body, headers)` and `Socket.connect(host, port)`, a script `weblingo` runs any host, a site only those its `wasp.config` allows, `{ "network": { "allow": ["api.example.com"] } }`. `std:db` supports SQLite, SQL Server, MySQL and PostgreSQL, `using (var db = await Database.open("fish")) { var rows = await db.query(sql, { max: 10 }); }`, a database named by `weblingo.config` or `wasp.config`, `{ "databases": { "fish": "sqlite:../database/fish.db" } }`, or by a connection string; `Examples.wasp/example2` is a fish store built on SQLite, and `Examples.wasp/example3` a to-do list on SQL Server. Errors go to standard error with their source location, code and exception class when available. The exit code is 0 on success, 1 for compilation errors or bytecode that cannot be used, 2 for a usage error, 3 for a runtime error, and 4 for a file that cannot be read or written. `wasp run [--root <folder>] <page.wasp>` and `wasp check [--root <folder>] <page.wasp>` do the same for a page, the page being written to standard output. `wasp serve [--root <folder>] [--port <port>]` serves an application, its pages and its other files, on <http://localhost:8080/>, or under IIS, through the ASP.NET Core Module, which a site's `web.config` has run `wasp serve`; and `wasp fastcgi [--root <folder>] [--port <port> | --socket <path> | --stdin]` serves it to a web server other than IIS, nginx or Apache, through FastCGI, as PHP-FPM serves PHP, on 127.0.0.1:9000 by default, or started by the web server itself, on its standard input, as Apache's mod_fcgid starts PHP. The repository's `Examples.wlg` holds scripts that show the language, each ending with what it writes, which `ExamplesTests` checks. The WebLingo Language Reference (`Documents/weblingo-language-reference.md`) describes the language, the WebLingo Standard Library Reference (`Documents/weblingo-standard-library-reference.md`) its built-in classes and standard modules, and the WASP User Manual (`Documents/wasp-user-manual.md`) shows how to write, serve and deploy a site. `Examples.wasp/example1`, at the repository's root, is such a site, its pages beside its `web.config`, as a PHP site's are. A page that declares `param request;` and `param response;` is given them: `request.method`, `request.path`, `request.query["id"]`, `request.headers["Accept"]`, `response.status = 404;`, `response.headers["Content-Type"] = "text/plain";`, and the request's body, `await request.text()`, or a form's fields, `(await request.form())["name"]`. A `.wlg` that exports `get(request, response)`, `post`, and so on, answers its route's methods, as `api/teas.wlg` answers `/api/teas`; any other method is a 405. A page's output is sent as it is written once it reaches 64 KB, and a page whose client is slow waits for it, without its worker, for at most 30 seconds, or the seconds a site's `wasp.config` gives, `{ "sendTimeout": 60 }`. A server has WebLingo installed once for all its sites, as PHP is: `../Installers/Windows/package.ps1` makes WebLingo's installers for Windows, zips of `weblingo` and the standard modules, with .NET's runtime or without it, which install WebLingo on a machine that has none (their `readme.md` says how), and WASP's, which then make its IIS run WASP's sites. `publish.ps1`, in this folder, publishes `wasp`, `weblingo` and the standard modules into `publish/WebLingo`, which a Windows server installs as `C:\Program Files\WebLingo`, where a site's `web.config` finds `wasp` (`Examples.wasp/README.md` says how).

## Architecture

See [`Documents/weblingo-architecture.md`](../Documents/weblingo-architecture.md) at the repository root; section 15 has M0.6's status, and the choices made where the specification is silent, all still proposed. WebLingo has one VM, a register VM (WL-BC002, the owner's choice of 23 November 2026), which the benchmark (`benchmarks/WebLingo.Benchmarks`) measures; the stack VM it was compared with was removed then, its last commit tagged `stack-vm-end`. Includes, layouts, and parameterized components are **all mandatory** for the first template-capable release; pages, their includes, components and layouts are implemented.
